# Пайплайн класса A

Детерминированные операции: тонировка, окрас дисков и суппортов, смена цвета
кузова глянец→глянец, звёздное небо, три световых условия. Внешняя модель
не вызывается ни разу.

```bash
cd app/worker
python3 experiment_specular.py          # проверка утверждения про блики
python3 run_class_a.py                  # прогон по набору кадров
```

## Что проверено измерением

**Отражения в лаке нельзя красить вместе с краской.** На чёрном кузове
наивная подмена цветности окрашивает яркие пиксели — те, где отражается
небо — в **6,3 раза сильнее**, чем саму краску. Кадр после этого читается
как подделка: небо в отражении становится цветным.

С отделением отражения сдвиг в ярких пикселях падает с 11,0 до 0,1 при том же
сдвиге в тёмных. То есть перекрашивается краска, а отражение остаётся
отражением.

| Кадр | Наивная (тёмные / яркие) | С сохранением бликов |
|---|---|---|
| Чёрный VW, отражение неба | 1,7 / 11,0 | 1,9 / **0,1** |
| Серебро на солнце | 7,1 / 4,1 | 7,1 / **0,8** |

**Направление по светлоте подтверждено.** Светлое → тёмное даёт результат,
который не отличить от съёмки. Тёмное → светлое вытягивает шум из заваленных
теней и даёт пятна — это класс B, и правило зашито в маршрутизацию
(`pipeline/route.py`).

## Ограничение, которое надо помнить

`relight()` строит три света сдвигом кривой по одному рендеру. Это корректно
для СПЛОШНОГО цвета. Для металликов, сатинов и хамелеонов отклик на свет
нелинейный, и сдвиг даст три яркости одного цвета — соврёт ровно на тех
артикулах, ради которых механика честности и существует. Такие SKU обязаны
иметь измеренный LAB (констрейнт в базе это требует) и идти тремя отдельными
проходами.

## Чего ещё нет

Сегментация. В опыте используется GrabCut по прямоугольнику — этого хватает,
чтобы проверить цветовую математику, но на результате видна граница маски
и не попадают бамперы. Настоящая работа — дообученная сеть на фиксированный
набор из ~20 классов; открытая словарная сегментация нам не нужна, словарь
закрыт и известен.
