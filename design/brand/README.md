# Знак YOOMP

Исходники — в `source/`, они же лежат в `~/Downloads/YOOMP` у основателя.
Веб-набор в `app/public/brand/` **выводится** из них скриптом `derive.py`,
а не копируется. Руками файлы в `app/public/brand/` не правятся: следующий
прогон скрипта их перезапишет.

```bash
python3 design/brand/derive.py
```

## Почему исходники не используются напрямую

**Лайм расходится с продуктом.** В растре он `#DEEC65`, фирменный `#DEF23B`.
Синий канал отличается на сорок два пункта. Рядом с кислотными плашками
интерфейса, где стоит ровно `#DEF23B`, это читается как другой цвет — то есть
знак выглядит чужим на собственном экране. Скрипт снимает лайм до покрытия и
красит точным, сохраняя сглаживание краёв.

**Прозрачные версии рыхлые.** В `04-transparent-lime` прозрачность получена
мягким ключом: у надписи 2164 полностью непрозрачных пикселя на два миллиона,
края мыльные. Поэтому прозрачность выводится из чистой версии на чёрном:
чёрное становится прозрачным, лайм остаётся лаймом.

Иконка — исключение. У неё чёрная плитка часть знака, и её надо сохранить,
поэтому она берётся из прозрачной версии, где вырезано только поле вокруг.

## Почему надпись в интерфейсе — текст, а не картинка

Фирменное начертание — курсив со срезами — это растр из генерации. На кегле
16px, каким имя стоит в шапке кабинета и на входе, он мылит. README самого
знака говорит то же: «перед печатью, плёнкой и мелкими кеглями знак нужно
отрисовать вектором».

Поэтому в интерфейсе стоит иконка (простая плитка, читается и в 28px) и имя
текстом из константы `BRAND`. Надпись картинкой используется только там, где
она большая: карточка ссылки.

**Когда появится вектор** — заменить текст на `wordmark.svg` в трёх местах:
`src/screens/chrome.tsx`, `src/app/login/page.tsx`, шапка и подвал
`src/app/(marketing)/sections.tsx`.
